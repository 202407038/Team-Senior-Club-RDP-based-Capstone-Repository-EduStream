# 구현 플레이북

## 1. 목적

이 문서는 팀원이 병렬로 작업할 때 서로 겹치지 않게 구현 범위를 나누고, 작업을 시작하고 끝내는 절차를 정리한 실무용 가이드입니다.

대상 상황:

- 최대 5명 개발 참여
- 실제 가용 인원은 3~5명 수준으로 변동 가능
- 한 번에 너무 큰 기능을 잡기보다, 리뷰 가능한 단위로 나눠서 진행

## 2. 권장 작업 분담

### 5명 모두 개발 가능한 경우

#### 1번 담당: 공통 코어/프로토콜

담당 범위:

- `EduStream.Core`
- 패킷 모델
- 직렬화기
- 공통 로깅
- 공통 유틸

주요 작업:

- 패킷 필드 구체화
- MessagePack 전환 준비
- 공통 예외 타입 정리

#### 2번 담당: 서버 세션/네트워크

담당 범위:

- `EduStream.Server/Services/SessionManager.cs`
- 서버 연결 흐름
- 브로드캐스트 구조

주요 작업:

- 세션 개설/종료
- 클라이언트 연결 관리
- TCP/UDP 역할 분리

#### 3번 담당: 서버 화면 송신

담당 범위:

- `ScreenCapturer`
- `RdpHost`
- 화면 송신 파이프라인

주요 작업:

- 화면 캡처
- 프레임 압축 또는 변환
- 송신 단위 정의

#### 4번 담당: 파일 전송

담당 범위:

- `FileDistributor`
- `FileReceiver`
- 파일 패킷 구조

주요 작업:

- 청크 분할
- 체크섬 검증
- 저장/실패 처리

#### 5번 담당: 클라이언트 UI/수신 상태

담당 범위:

- `EduStream.Client`
- `ClientViewModel`
- WPF 상태 표시

주요 작업:

- 연결 상태 표현
- 화면 렌더 상태 반영
- 채팅/다운로드 UI 고도화

## 3. 가용 인원이 적을 때의 축소 운영

### 4명일 때

- 공통 코어 담당은 유지
- 서버 세션 + 파일 전송을 한 명이 묶어서 담당
- 서버 화면 송신은 별도 유지
- 클라이언트 UI/수신은 별도 유지

### 3명일 때

- 1명: 공통 코어 + 프로토콜
- 1명: 서버 전체
- 1명: 클라이언트 전체

### 2명 이하일 때

아래 순서로만 진행합니다.

1. 공통 코어
2. 채팅
3. 파일 전송
4. 화면 스트리밍

즉, 가장 위험도가 큰 화면 스트리밍은 마지막에 넣습니다.

## 4. 각 팀원의 작업 시작 절차

1. `main` 최신화
2. 본인 작업 브랜치 생성
3. 담당 파일 범위 확인
4. 설계 문서 확인
5. 작업 시작

권장 명령:

```bash
git checkout main
git pull origin main
git checkout -b feature/<작업명>
```

## 5. 각 팀원의 작업 종료 절차

1. 로컬 빌드
2. 불필요한 파일 제거 여부 확인
3. 커밋
4. 푸시
5. PR 생성
6. 리뷰 요청

## 6. 기능별 권장 구현 순서

### 채팅

1. `ChatPacket` 필드 확정
2. 서버 송신 메서드 추가
3. 클라이언트 수신 메서드 추가
4. UI 바인딩 반영
5. 다중 메시지 흐름 확인

### 파일 전송

1. `FilePacket` 메타데이터 확정
2. 체크섬 계산 로직 고정
3. 청크 분할 설계
4. 서버 송신
5. 클라이언트 수신/검증/저장
6. 실패 시 재시도 규칙 정의

### 화면 스트리밍

1. 캡처 방식 결정
2. 프레임 데이터 구조 확정
3. 송신 주기 결정
4. 클라이언트 렌더링 연결
5. 지연/성능 측정

## 7. 작업 충돌을 줄이는 방법

- 같은 클래스 파일을 두 사람이 동시에 크게 수정하지 않습니다.
- 구조 변경 PR이 열려 있으면, 그 구조에 의존하는 기능 PR은 기다리거나 분기 범위를 줄입니다.
- ViewModel 변경과 서비스 변경이 모두 필요한 경우, 담당을 나눴다면 인터페이스나 메서드 시그니처를 먼저 합의합니다.

## 8. 권장 이슈 단위

한 PR에는 아래 정도 규모가 적당합니다.

- 채팅 패킷 구조 추가
- 클라이언트 파일 저장 기능 추가
- 서버 세션 종료 흐름 보완
- 화면 렌더링 상태 표시 개선

피해야 하는 묶음:

- 채팅 + 파일 전송 + 화면 송신을 한 PR에 같이 넣는 것

## 9. 문서 반영 규칙

아래 상황에서는 문서도 함께 수정합니다.

- 새 패키지 추가
- 새로운 외부 라이브러리 도입
- 브랜치 전략 변경
- 코딩 규칙 변경
- UML 구조 변경
