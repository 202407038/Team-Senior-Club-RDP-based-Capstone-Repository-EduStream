# 7일 스프린트 상세 구현 가이드

## 1. 문서 목적

이 문서는 현재 프로젝트 상태와 이미 반영된 공통 코어 계약을 기준으로, 개발 팀원 5명이 7일 동안 무리하지 않고 진행할 수 있는 현실적인 구현 계획을 정리한 문서입니다.

이번 스프린트의 핵심은 "끝까지 닫히는 최소 흐름"을 만드는 것입니다.

- 세션 개설
- 세션 참여
- 채팅 송수신 흐름
- 파일 전송 기본 흐름
- 화면 스트리밍은 본격 구현보다 전송 구조 검증과 준비 수준까지

## 2. 작업 시작 전 공통 규칙

모든 개발 팀원은 작업 시작 전에 아래 명령을 먼저 실행합니다.

```bash
git pull --all --prune
```

권장 순서:

```bash
git checkout main
git pull --all --prune
git checkout -b feature/<작업명>
```

이 규칙은 선택이 아니라 기본 절차로 봅니다.

이유:
- 이미 머지된 PR을 놓치지 않기 위해
- 브랜치 정리 상태를 최신으로 맞추기 위해
- 같은 파일을 오래된 기준으로 수정하는 일을 줄이기 위해

## 3. 이번 스프린트 목표

### 필수 목표

- 세션 개설 및 참여 흐름이 코드상으로 연결된다.
- 공통 패킷 구조를 기준으로 채팅과 파일 전송 흐름이 이어진다.
- 클라이언트 UI에서 연결 상태, 채팅 상태, 파일 수신 상태를 확인할 수 있다.

### 권장 목표

- 파일 청크 전송 흐름이 한 번 이상 end-to-end로 검증된다.
- 화면 공유는 프레임 데이터 생성과 렌더링 연결까지 기본 흐름을 확인한다.

### 이번 스프린트에서 무리하지 않을 것

- 고성능 화면 스트리밍 최적화
- 복구 재전송 로직 완성
- 복잡한 예외 복구 시나리오 전부 처리
- MessagePack 전환
- 실제 RDP 연동 완성

## 4. 5명 역할 분담

### 1번. 공통 코어 / 프로토콜 담당

담당 범위:
- `EduStream.Core`
- 패킷 모델
- 체크섬 유틸
- 응답 코드
- 직렬화 구조

이번 스프린트 목표:
- 패킷 구조 추가 변경 최소화
- 파일/세션/오류 공통 규칙 마무리
- 다른 팀원이 바로 참고할 수 있게 기준 고정

### 2번. 서버 세션 / 네트워크 담당

담당 범위:
- `SessionManager`
- 서버 연결 흐름
- 세션 개설 / 종료
- join / leave 처리

이번 스프린트 목표:
- 서버 세션 흐름을 최소 동작 상태로 만들기
- 참여자 수 갱신 흐름 안정화
- Ack / Error 패킷 처리 기준 서버 쪽에 연결

### 3번. 서버 화면 송신 담당

담당 범위:
- `ScreenCapturer`
- `RdpHost`
- 화면 전송용 패킷 준비

이번 스프린트 목표:
- 실제 고성능 스트리밍 완성보다
- 캡처 데이터 생성 -> `ScreenPacket` 구성 -> 클라이언트 전달 구조 확인

### 4번. 파일 전송 담당

담당 범위:
- `FileDistributor`
- `FileReceiver`
- 파일 청크 전송 흐름

이번 스프린트 목표:
- 파일 메타데이터 / 체크섬 / 청크 분할 기준 마무리
- 수신 후 저장까지 최소 1회 흐름 검증

### 5번. 클라이언트 UI / 수신 담당

담당 범위:
- `EduStream.Client`
- `SessionClient`
- `ClientViewModel`
- 연결 / 채팅 / 다운로드 상태 UI

이번 스프린트 목표:
- 사용자 입장에서 "연결됨 / 수신됨 / 저장됨 / 실패함" 상태가 보이도록 만들기

## 5. 7일 상세 작업표

### Day 1. 기준 정리 및 진입

공통:
- 모든 팀원 `git pull --all --prune` 실행
- 최신 `main` 기준으로 각자 브랜치 생성
- README / docs / UML / 코어 모델 다시 확인

1번:
- 코어 패킷 구조 최종 점검
- Ack / Error / Checksum / SessionEndpoint 기준 정리

2번:
- SessionManager 흐름 점검
- join / leave / session open / close 메서드 연결 상태 확인

3번:
- 현재 ScreenPacket 기준 검토
- 캡처 데이터 포맷 후보 정리

4번:
- FileDistributor / FileReceiver 흐름 점검
- 청크 단위 기준 재확인

5번:
- ClientViewModel 상태 표시 항목 정리
- 연결 / 채팅 / 다운로드 UI 점검

### Day 2. 세션 / 채팅 최소 흐름 연결

1번:
- 코어 변경 필요 시 소규모 수정만 수행
- 패킷 변경은 최소화

2번:
- 세션 개설 / 참여 / 종료 흐름 보강
- 서버 로그와 상태 업데이트 정리

5번:
- 클라이언트 join / leave / 상태 표시 연결
- Ack / Error 반영 UI 정리

이번 날 목표:
- 세션이 열리고 참여되며 종료되는 흐름이 스켈레톤 수준을 넘어서도록 만들기

### Day 3. 채팅 흐름 마무리

1번:
- 채팅 패킷 추가 보강 필요 여부만 검토

2번:
- 서버 측 채팅 브로드캐스트 흐름 연결

5번:
- 클라이언트 채팅 표시 흐름 연결
- 송신/수신 메시지 로그 반영

이번 날 목표:
- 교수자/수강생 채팅 흐름이 코드 기준으로 이어지도록 만들기

### Day 4. 파일 전송 기본 흐름 구현

1번:
- 파일 전송 관련 공통 규칙 변경이 필요하면 작은 범위에서만 반영

4번:
- 청크 분할
- 체크섬 생성
- 저장 전 검증
- 다운로드 결과 상태 처리

5번:
- 파일 수신 상태 UI 보강

이번 날 목표:
- 작은 샘플 파일 기준으로 송신 -> 수신 -> 저장 흐름이 보이도록 만들기

### Day 5. 파일 전송 안정화 + 화면 전송 준비

4번:
- 파일 전송 경계 조건 점검

### Day 6. 화면 공유 흐름 점검 및 통합 테스트

- 세션 흐름과 화면 전송 경로 충돌 확인

- 화면 송신 흐름 통합 점검

5번:
- 클라이언트 렌더 상태 점검

### Day 7. 정리 / PR / 머지 준비

공통:
- 각자 브랜치 정리
- 로컬 빌드
- 불필요 파일 확인

1번:

전체:
- 머지 가능한 작업부터 순차 PR
- 다음 스프린트로 넘길 항목 정리

## 6. 하루 작업량 기준

각 팀원은 하루에 아래 정도만 목표로 잡는 것을 권장합니다.

- 작은 기능 1개 완료
- 또는 기능 1개 + 테스트/문서 반영
- 또는 화면/파일/세션 중 한 흐름의 일부 연결

권장하지 않는 방식:
- 하루에 채팅, 파일, 화면을 동시에 끝내려는 계획
- 세션/파일/UI를 한 PR에 전부 넣는 방식

## 7. PR 단위 권장

좋은 PR 예시:
- `feat: connect session join and leave flow`
- `feat: add file chunk receive validation`
- `feat: wire chat flow to client view model`

좋지 않은 PR 예시:
- 채팅 + 파일 전송 + 화면 공유를 한 번에 넣는 큰 PR

## 8. 이번 스프린트 종료 기준

이번 스프린트가 성공했다고 볼 수 있는 기준:

- 세션 개설 / 참여 / 종료 흐름이 확인된다.
- 채팅 흐름이 확인된다.
- 파일 전송 최소 흐름이 확인된다.
- 화면 공유는 적어도 프레임 전달 구조가 검증된다.
- README / docs / UML / 코드 사이 큰 불일치가 없다.
