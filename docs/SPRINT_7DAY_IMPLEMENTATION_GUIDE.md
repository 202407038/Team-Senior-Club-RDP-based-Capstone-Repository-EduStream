# 7일 스프린트 상세 구현 가이드

## 1. 문서 목적

이 문서는 현재 프로젝트 상태와 이미 반영된 공통 코어 계약을 기준으로, 개발 팀원 5명이 7일 동안 실제로 구현해야 하는 작업을 상세하게 정리한 스프린트 가이드입니다.

기존 계획보다 작업량을 더 촘촘하게 잡되, 무리하게 “완성품”을 요구하기보다는 다음 조건을 만족하는 것을 목표로 합니다.

- 세션 흐름이 서버/클라이언트에서 실제로 이어진다.
- 채팅, 파일 전송, 화면 송신이 각각 독립적으로 검증 가능하다.
- UI에서 연결 상태와 수신 상태가 실제 코드 흐름과 연결된다.
- 7일차 시점에 “설명 가능한 데모”가 아니라 “직접 실행 가능한 데모”가 된다.

## 2. 작업 시작 전 공통 규칙

모든 개발 팀원은 작업을 시작하기 전에 아래 명령을 먼저 실행합니다.

```bash
git pull --all --prune
```

권장 순서는 다음과 같습니다.

```bash
git checkout main
git pull --all --prune
git checkout -b feature/<작업명>
```

이 규칙은 선택 사항이 아니라 기본 절차입니다.

이유:
- 이미 머지된 PR을 놓치지 않기 위해
- 브랜치 정리 상태를 최신으로 맞추기 위해
- 오래된 구조 기준으로 개발하는 일을 줄이기 위해

## 3. 이번 스프린트 목표

### 필수 목표

- 서버에서 세션을 열고, 클라이언트가 참가할 수 있다.
- 참가/이탈/오류 응답이 UI와 로그에 반영된다.
- 채팅 메시지가 양방향으로 전달되고, 서버/클라이언트 UI 양쪽에서 확인 가능하다.
- 파일 전송은 청크 단위로 송신/수신/검증/저장 흐름이 이어진다.
- 화면 송신은 최소한 서버 캡처 -> 패킷 구성 -> 클라이언트 수신 상태 반영까지 이어진다.

### 권장 목표

- 다중 클라이언트 2명 이상 기준으로 세션/채팅/파일 흐름을 검증한다.
- 파일 전송 실패 또는 체크섬 오류 시 UI에 실패 상태가 반영된다.
- 화면 송신 패킷의 메타데이터와 렌더 상태가 로그와 UI 모두에 표시된다.
- 데모 시나리오를 그대로 따라갈 수 있을 만큼 동작 순서가 정리된다.

### 이번 스프린트에서 끝까지 무리하지 않을 것

- 고성능 화면 스트리밍 최적화
- RDP 기반 구조의 최종 확정
- 완전한 재전송/복구 로직
- MessagePack 전환
- 운영 환경 배포 품질

## 4. 5명 역할 분담

### 1번. 공통 코어 / 프로토콜 담당

담당 범위:
- `EduStream.Core`
- 패킷 모델
- 직렬화기
- 공통 유틸
- 에러/응답 코드
- 전송 검증 규칙

이번 스프린트 목표:
- 패킷 계약을 최종 고정에 가깝게 다듬기
- 다른 담당자가 별도 해석 없이 사용할 수 있게 기준을 문서와 코드에 함께 남기기
- 파일/화면/세션 관련 공통 검증 규칙을 코어로 끌어올리기

### 2번. 서버 세션 / 네트워크 담당

담당 범위:
- `SessionManager`
- 서버 세션 개설/종료
- join / leave / ack / error 처리
- 참가자 수 갱신
- 연결 상태 관리

이번 스프린트 목표:
- 세션 흐름이 실제 네트워크 송수신과 연결되도록 만들기
- 참가자 수, 접속 상태, disconnect 처리까지 서버 기준을 안정화하기

### 3번. 서버 화면 송신 담당

담당 범위:
- `ScreenCapturer`
- 화면 프레임 생성
- `ScreenPacket` 구성
- 서버 화면 송신 진입점

이번 스프린트 목표:
- 빈 스텁이 아니라 실제 프레임 데이터가 흐르도록 만들기
- 화면 송신 흐름과 패킷 메타데이터를 정리하고, 이후 스트리밍 최적화 전에 검증 가능한 상태까지 끌고 가기

### 4번. 파일 전송 담당

담당 범위:
- `FileDistributor`
- `FileReceiver`
- 파일 청크 전송
- 체크섬 검증
- 저장 결과 처리

이번 스프린트 목표:
- 작은 파일과 중간 크기 파일 기준으로 송신/수신/저장 흐름을 end-to-end로 검증하기
- 실패 시나리오를 최소 1개 이상 고려해 UI와 로그까지 연결하기

### 5번. 클라이언트 UI / 수신 담당

담당 범위:
- `EduStream.Client`
- `SessionClient`
- `ClientViewModel`
- 연결/채팅/파일/화면 상태 UI

이번 스프린트 목표:
- 사용자가 지금 무엇을 하고 있는지, 어떤 상태인지, 성공/실패가 무엇인지 UI에서 읽히게 만들기
- 서비스에서 들어오는 결과를 화면 상태와 로그에 반영하기

## 5. 7일 상세 작업표

### Day 1. 기준선 정리와 진입

공통:
- `git pull --all --prune` 실행
- `main` 최신화 후 개인 브랜치 생성
- README / docs / UML / 주요 서비스/모델 재확인
- 각자 “이번 주 내가 직접 건드릴 파일” 목록 확정

1번:
- `BasePacket`, `PacketType`, `AckPacket`, `ErrorPacket`, `HeartbeatPacket` 점검
- `FilePacket`, `ScreenPacket`, `SessionJoinPacket`, `SessionLeavePacket` 필드 재검토
- `AckCodes`, `ErrorCodes`, `ChecksumUtility`, `SessionEndpoint`, `FileTransferUtility`, `ScreenTransferUtility` 기준 재확인
- 누락된 공통 모델/유틸 후보 목록 작성

2번:
- `SessionManager`, `TcpServerService`, `HeartbeatService` 구조 재점검
- session open / close / join / leave / disconnect 흐름 확인
- 로그 기준과 참가자 수 갱신 지점 확인

3번:
- `ScreenCapturer`, `ScreenPacket`, `ScreenRenderer` 흐름 점검
- 현재 캡처 포맷과 인코딩 규칙 확인
- 송신 주기/프레임 메타데이터 정리

4번:
- `FileDistributor`, `FileReceiver`, `FilePacket` 흐름 점검
- 청크 크기/체크섬/임시 저장 규칙 점검
- 테스트용 샘플 파일 전략 정리

5번:
- `ClientViewModel`, `MainWindow.xaml`, `SessionClient` 점검
- 세션/채팅/파일/화면 상태 패널 확인
- 실제 서비스 결과와 UI 상태 바인딩 지점 파악

### Day 2. 세션 흐름과 코어 규칙 보강

1번:
- 공통 패킷 생성 규칙 보강
- 공통 팩토리/헬퍼가 필요하면 추가
- 프로토콜 버전, 공통 에러 코드, 공통 응답 코드 정리
- 서버/클라이언트가 중복으로 갖는 문자열/검증 규칙 정리

2번:
- 세션 개설/종료 흐름 안정화
- join / leave 시 ack/error 패킷 반환 흐름 정리
- disconnect 시 자동 이탈 처리 점검
- 참가자 목록과 UI 이벤트 연결 확인

5번:
- 세션 참가/종료 UI를 실제 흐름에 맞춰 정리
- ack/error를 연결 상태와 안내 메시지에 반영
- 세션 정보 표시 패널 정리
- 서버 메시지/오류 표시 기준 정리

### Day 3. 채팅 흐름 완성

1번:
- `ChatPacket` 필드와 직렬화 흐름 최종 점검
- 다형성 직렬화/역직렬화 문제 여부 검토
- 채팅 관련 공통 팩토리나 공통 파서 필요 여부 점검

2번:
- 서버 채팅 브로드캐스트 흐름 점검
- 송신자 정보/로그/오류 처리 정리
- 다중 참여자 기준으로 채팅 전달 흐름 검증

5번:
- 클라이언트 채팅 입력/출력 UI 정리
- 채팅 전송 버튼 상태, 빈 메시지 처리, 로그 반영 정리
- 서버에서 들어오는 채팅 메시지가 클라이언트 UI에 쌓이도록 정리
- 서버 UI에도 채팅 수신이 보이도록 확인

### Day 4. 파일 전송 흐름 고도화

1번:
- 파일 전송 검증 규칙을 공통 코어 기준으로 보강
- 파일명/크기/청크 인덱스/총 청크 수/체크섬 검증 규칙 최종 점검
- 필요시 공통 검증 유틸 보강

4번:
- 청크 분할 로직 보강
- 파일 송신 메서드와 수신 조립 흐름 점검
- 메타데이터 불일치, 체크섬 불일치, 잘못된 청크 인덱스 처리 정리
- 저장 완료 시점과 실패 시점 구분

5번:
- 다운로드 상태 UI 보강
- 다운로드 목록, 마지막 수신 결과, 실패 메시지 표시
- 파일 수신 진행 흐름을 사용자가 이해할 수 있게 정리

### Day 5. 화면 송신/수신 흐름 고도화

1번:
- `ScreenPacket` 메타데이터 규칙 점검
- 인코딩/폭/높이/프레임 인덱스/전송 길이 검증 기준 점검
- 화면 패킷 공통 규칙 보강

3번:
- 실제 캡처 프레임 생성 로직 보강
- 캡처 실패 시 fallback 프레임 처리
- `ScreenPacket`에 메타데이터를 정확히 채우는지 확인
- 서버에서 화면 송신 진입점이 재사용 가능하도록 정리

5번:
- 화면 수신 상태 UI 보강
- 렌더 상태 문자열, 최근 프레임 정보, 실패 상태 표시
- 파일 상태 패널과 화면 상태 패널이 겹치지 않게 구조 정리

### Day 6. 통합 테스트와 다중 흐름 검증

공통:
- 세션 + 채팅 + 파일 + 화면 흐름을 묶어서 테스트
- 기능 간 충돌 확인
- 문서와 실제 구현 차이 확인

1번:
- 공통 코어 변경이 서비스 계층과 어긋나지 않는지 최종 점검
- 누락된 상수, 유틸, 공통 규칙 보강

2번:
- 다중 클라이언트 기준 세션 흐름 점검
- disconnect / reconnect / leave 처리 확인

3번:
- 화면 송신이 파일/채팅 흐름과 동시에 동작하는지 확인
- 최소한 프레임 생성/전송 상태가 무너지지 않는지 확인

4번:
- 청크 파일 수신/저장 테스트 반복
- 실패 시나리오 1개 이상 직접 확인

5번:
- UI에서 상태가 모두 읽히는지 점검
- 로그, 상태 문구, 패널 배치, 버튼 활성/비활성 점검

### Day 7. 정리 / PR / 머지 준비

공통:
- 로컬 빌드
- 불필요한 파일 제거
- 문서 반영 여부 확인
- PR 단위 정리

1번:
- 코어 변경이 다른 담당자 작업과 충돌 없는지 최종 점검
- 공통 클래스/유틸 변경 범위가 과하지 않은지 점검

2번~5번:
- 기능별로 리뷰 가능한 최소 단위로 PR 정리
- 머지 후 시연 순서대로 기능 점검

전체:
- 시연 가능한 최소 흐름 점검
- 다음 스프린트에서 할 일 분리

## 6. 권장 PR 단위

좋은 PR 예시:
- `feat: stabilize session join and leave flow`
- `feat: add shared file transfer validation rules`
- `feat: add server screen preview packet flow`
- `feat: redesign client session and chat workflow UI`

좋지 않은 PR 예시:
- 채팅 + 파일 전송 + 화면 송신 + UI 전체를 한 번에 넣는 PR

## 7. 이번 스프린트 종료 기준

이번 스프린트가 성공이라고 볼 수 있는 기준:

- 서버에서 세션을 열 수 있다.
- 클라이언트가 세션에 참가/이탈할 수 있다.
- 채팅이 양방향으로 보인다.
- 파일 전송 최소 흐름이 검증된다.
- 화면 프레임 송신/수신 상태가 검증된다.
- README / docs / UML / 코드 간 큰 불일치가 없다.
