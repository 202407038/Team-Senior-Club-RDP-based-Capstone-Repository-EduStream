## 2·3·5번 연동 계약

1. 강의 참가가 승인된 뒤 Create(sessionId, participantId)로 상태를 만듭니다. 이 모델 자체는 참가 권한을 검증하지 않습니다.
2. 연결 시도마다 새 Guid를 생성하고 BeginConnect를 호출합니다.
3. 실제 RDP 어댑터의 연결 성공 콜백에서 Connected(connectionId)를 호출합니다. 미리보기 창 생성이나 PNG 수신은 성공 근거가 아닙니다.
4. 실제 오류를 RdpFailureReason으로 변환하여 Fail을 호출합니다. NetworkInterrupted/HostUnavailable만 자동 재시도 가능한 것으로 분류합니다.
5. 재접속은 새 연결 ID로 시작합니다. 이전 연결 콜백이 들어오면 현재 상태를 바꾸지 말고 진단 로그에 남깁니다.
6. 세션 종료/참가자 이탈 시 Close를 호출합니다. Closed 상태를 재사용하지 않고 새 세션/참가 승인으로 새 상태를 만듭니다.
7. 모델은 불변입니다. 반환값을 보관해야 하며 어댑터에서 이벤트 적용을 직렬화해야 합니다. 참가자별 상태를 별도로 보관합니다.

RDP 자격 증명, 초대 토큰, 화면 본문은 이 모델에 넣지 않습니다. RDP 스트림을 기존 ScreenPacket(PNG)에 포장하지 않습니다. 기존 PacketType/ProtocolVersion은 변경하지 않았습니다. 공급자 선택 후 연결 정보의 구체 형식과 네트워크 제어 메시지 라우팅은 2·3번과 연동해야 합니다.

## 채팅 및 파일 계약

- 사용자/시스템 메시지 생성에는 PacketFactory를 사용합니다. 길이는 글자 수가 아니라 UTF-8 바이트 수입니다.
- IsSystemMessage는 신뢰할 수 있는 서버가 결정해야 합니다. 클라이언트가 보낸 플래그만으로 시스템 메시지 권한을 부여하지 않습니다.
- 저장 오류 문자열은 기존 FileReceiver와 동일하므로 기존 수신 경로와 호환됩니다.
- FeatureOperationResult의 파일/채팅 상태와 RdpConnectionStatus를 구분해서 관리합니다.

## 5주차 시연 설명 및 기록

설명: “강의 세션 ID와 학생 ID로 연결을 구분하고, 재접속 시 새 연결 ID를 발급하여 이전 연결 이벤트가 현재 화면 상태를 바꾸지 않도록 처리.”

실제 RDP 어댑터 연동 후 시간·sessionId·participantId·connectionId·이전/현재 상태·실패 원인을 기록합니다. 비밀번호/초대 토큰은 기록하지 않습니다.

## 아직 완료되지 않은 항목

- 실제 RDP 공급자/연결 정보 형식 결정과 서버·학생 UI 소비 코드 연결.
- 실제 다중 PC의 학생 2명 RDP 연결/재접속/종료 증빙.
- 실제 RDP+파일+채팅 병행, 15분 실행 및 전체 시연 2회.
- 모델 테스트를 RDP 네트워크/화면 품질 테스트로 표현하지 않습니다.
