# 실행 및 설정 가이드

갱신: 2026-10-04. 화면 공유 기본 경로는 **WDS 기반 RDP**이며 PNG 버튼은 보조 테스트입니다. 아래 개발 브랜치와 기존 배포물은 실행 절차가 다르므로 구분합니다. 이 문서는 코드/버튼 확인 기준이며 최신 다중 PC 수동 시연 완료 기록은 아닙니다.

## 현재 main / preview.3: 접속 코드 없는 LAN 참가

main `28bbfa9` (#68~#70), 실행용 ZIP `v0.1.0-preview.3`의 절차입니다. **기존 preview.2는 자동 갱신되지 않으며 접속 코드를 요구합니다.** 교수자와 학생은 같은 버전을 사용합니다. 최종 UI(#65/#67)는 아직 미병합이므로 현재 학생 설정 영역에서 참가 정보를 입력합니다. 새 시안을 기존 main 배치로 되돌린 것이 아닙니다.

1. 신뢰하는 동일 LAN에서 사용합니다. 일반 사용자는 preview.3 ZIP을 전체 압축 해제하고 교수자/학생 EXE를 더블클릭합니다. 소스 개발자는 `dotnet build EduStream.sln` 후 교수자 `dotnet run --project src/EduStream.Server/EduStream.Server.csproj --no-build`, 학생 `dotnet run --project src/EduStream.Client/EduStream.Client.csproj --no-build`로 실행합니다. 같은 PC에서는 교수자부터 실행합니다.
2. 교수자 **호스트 IP** 목록에서 실제 학생 PC와 연결되는 LAN/Wi-Fi 주소를 골라 **IP 복사**로 전달합니다. VPN/가상 NIC 주소와 구분합니다. `127.0.0.1`/루프백은 같은 PC 점검용이지 다른 학생 PC에 알려줄 주소가 아닙니다.
3. **방 비밀번호**를 입력하거나 무비밀번호 방이면 비워 두고 **세션 열기**를 누릅니다. 세션 이름이나 접속 코드를 입력/전달하지 않습니다. 열린 방의 비밀번호를 바꾸려면 **세션 닫기 → 비밀번호 입력 → 다시 열기**를 사용합니다(기존 참가자는 퇴장하므로 수업 중 임의 변경하지 않습니다).
4. 학생은 표시 이름·교수자 IP·방 비밀번호(설정한 경우만)를 입력하고 **세션 참여**를 누릅니다. 기본 포트는 5000이며 수정할 필요가 없습니다. 충돌 등으로 바꿀 때만 양쪽의 기본 접힘 **고급 연결 설정**을 열어 같은 포트를 지정합니다. TLS 채널은 자동으로 포트+1을 사용합니다.
5. 교수자 **WDS 공유 시작** 후 초대/비밀 전달과 학생 RDP 연결은 기존 자동 경로를 이용합니다. 학생에게 별도 접속 코드·RDP 비밀번호·첫 접속 신뢰 확인을 요구하지 않습니다. 공유 재시작 및 통신 단절 재연결도 코드 입력을 받지 않습니다. 실제 화면 복귀/움직임은 다중 PC에서 별도 확인해야 합니다.
6. 파일 등록·학생 요청 다운로드·채팅은 아래 preview.2의 기능 안내를 참고합니다. 잘못된 방 비밀번호는 참가 거부, 무비밀번호 방은 빈 값 참가, 종료한 세션에는 자동 복귀하지 않는지 확인합니다. 개발자용/구형 RDP 버튼이 남아 있는 것을 최종 UI 완료로 판단하지 않습니다.

TLS 암호화와 방 인증/티켓/권한 검사는 유지하지만 인증서 지문 대조는 하지 않으므로 **입력 IP의 상대가 실제 교수자라는 신원 보장은 없습니다.** 비신뢰 LAN/인터넷용으로 안내하지 않습니다. 인증서 오류·방 비밀번호 오류·주소/포트 오류는 구분해 확인하며 평문 우회, 방화벽 전체 해제는 하지 않습니다. 비밀번호·초대 비밀·재연결 토큰은 로그/공개 캡처에 넣지 않습니다.

## 이전 배포 ZIP preview.2 및 당시 소스 실행 (#58·#59·#61 반영)

2026-09-30 실행용 ZIP `v0.1.0-preview.2`는 main `013c2d0`의 앱 코드를 포함합니다. 양쪽 모두 이 ZIP을 전체 압축 해제한 뒤 교수자/학생 EXE를 실행하면 아래 2번 이후 절차를 사용할 수 있으며 SDK·빌드 명령은 필요하지 않습니다. [ZIP 실행 안내](./DESKTOP_LAUNCH.md). 아래 1번과 dotnet 명령은 소스 개발용입니다. 9/15 `preview.1`은 자동 갱신되지 않습니다. 배포는 ZIP만 유지하며 GitHub `Code → Download ZIP`은 개발용 소스입니다.

1. Windows x64에 .NET 8 SDK를 준비하고 최신 소스를 별도 폴더에 받습니다. `EduStream.sln` 폴더에서 `dotnet build EduStream.sln` → `dotnet test EduStream.sln --no-build`를 실행합니다. 아래 환경 점검 절차도 참고합니다.
2. 교수자부터 `dotnet run --project src/EduStream.Server/EduStream.Server.csproj --no-build`로 실행합니다. 같은 Windows 로그인 환경에서는 학생이 먼저 켜져 있으면 교수자 실행이 제한됩니다. 다른 PC 전체에 적용하는 제한은 아닙니다.
3. 현재 UI의 세션 이름/포트(기본 5000)를 확인합니다. **방 비밀번호**는 지정하거나 빈 값으로 둡니다. **세션 열기** 후 표시되는 **접속 코드**를 학생에게 정확히 전달합니다. 접속 코드는 교수자 인증서 확인용이며 방 비밀번호와 다릅니다. 방 비밀번호가 없어도 접속 코드는 필요합니다.
4. 교수자 **WDS 공유 시작**을 누릅니다. 현재 교수자 화면에 있는 개인정보/비밀번호/사적인 창은 미리 닫습니다. Windows 로그인 비밀번호를 입력하는 방식이 아닙니다.
5. 학생 PC에서 `dotnet run --project src/EduStream.Client/EduStream.Client.csproj --no-build`로 실행합니다. **설정**에서 표시 이름·호스트·포트·접속 코드·방 비밀번호(있는 경우)를 입력하고 **세션 참여**를 누릅니다. 다른 PC에서는 교수자 로컬 IPv4를 쓰며 `127.0.0.1`은 같은 PC 점검용입니다.
6. 참가 승인 후 초대와 비밀이 각각 도착하면 자동 RDP 연결을 시도합니다. **초대 비밀번호 복사/붙여넣기와 RDP 연결 버튼은 정상 흐름에서 필요하지 않습니다.** 구형 수동 UI가 남아 있는 것과 자동 경로 미구현을 혼동하지 않습니다.
7. 학생이 공유 시작 전에 참가했거나 교수가 공유를 중지/재시작하면 세션은 유지하고 초대를 다시 받아 연결하는 경로를 사용합니다. 자동 테스트는 초대 전달/Connect 호출까지이며 실제 화면 복귀는 직접 확인해야 합니다. 연결 실패 후에는 **RDP 재접속**으로 새 초대를 요청하고, 같은 실패 초대를 반복 사용하는 것으로 복구를 판단하지 않습니다.
8. 파일은 교수자 **파일 선택 → 강의 파일 목록에 등록**, 학생 **파일 탭 → 강의 파일 → 다운로드**를 사용합니다. 이 경로는 Windows 다운로드 폴더에 저장하며 동명 파일을 덮어쓰지 않습니다. 교수자의 **해제**는 목록/추가 다운로드를 없애지만 학생이 이미 저장한 사본은 지우지 않습니다.
9. **선택 파일 전송/샘플 파일 전송**은 기존 즉시 전송 경로입니다. 요청형 등록과 다르며, 구형 받은 파일의 임시 폴더 경로를 새 다운로드 경로로 안내하지 않습니다. 파일명 클릭/드롭과 최종 화면 배치는 5번 UI 인수가 별도로 필요합니다.
10. 두 학생의 실제 화면 전환, 채팅, 원본/수신 파일 SHA256, 공유 중지/재시작, 학생 종료/재참가를 차례로 확인합니다. 교수자 세션 종료/정상 퇴장 후에는 자동 재참가하지 않아야 합니다. 최신 변경으로 실제 역방향 화면·원격 입력·판서까지 완료된 것은 아닙니다.

접속 실패 시 호스트/포트·접속 코드·방 비밀번호를 구분해 점검합니다. TLS 인증 실패를 무시하거나 평문 접속으로 우회하지 않습니다. 보호 채널은 강의 포트+1(기본 TCP 5000이면 TLS 5001)을 사용하며 학생 입력은 강의 포트 하나입니다. WDS 연결 포트는 이 둘이나 3389로 고정 가정하지 않습니다. 방화벽 전체 해제/인터넷 포트 개방으로 우회하지 않고 신뢰 네트워크 범위의 앱/포트 허용을 확인합니다. 로그나 공개 캡처에 방 비밀번호·초대 비밀·재연결 토큰을 넣지 않습니다.

## 1. 준비와 설치

1. 교수자 Windows PC 1대, 학생 Windows PC 2대를 준비합니다. 먼저 같은 신뢰할 수 있는 로컬 네트워크에서 점검합니다. 이 저장소의 WPF/COM 구현은 Windows 대상입니다.
2. [.NET 8 공식 다운로드](https://dotnet.microsoft.com/en-us/download/dotnet/8.0)에서 **Build apps - SDK → Windows x64** 설치 파일을 선택합니다. 이 가이드는 x64 환경 기준입니다. 설치 파일 실행 → 설치 → 완료 후 터미널을 새로 엽니다. 런타임만 설치하면 소스 빌드를 할 수 없으므로 SDK를 선택합니다.
3. PowerShell에서 `dotnet --list-sdks`를 실행해 SDK가 보이는지 확인합니다. 이미 호환 SDK로 빌드가 성공하는 PC는 재설치할 필요가 없습니다.
4. [GitHub 저장소 main](https://github.com/202407038/Team-Senior-Club-RDP-based-Capstone-Repository-EduStream/tree/main)에서 같은 코드 버전을 준비합니다. Code → Download ZIP → 압축 풀기를 사용하거나 기존 Git 작업본을 사용합니다.
5. `EduStream.sln`이 있는 폴더를 파일 탐색기로 열고 주소창에 `powershell`을 입력합니다.

팀장 PC의 예전 바깥 저장소와 `backups/migration-20260525`를 혼동하지 않습니다. 별도 worktree에서 실행할 때도 `EduStream.sln`과 최신 커밋을 확인합니다. 기존 수정/백업이 있는 폴더에 ZIP을 덮어쓰거나 Git 초기화를 하지 않습니다.

Git 작업본이라면 먼저 아래 내용을 확인합니다. 로컬 수정이 있으면 보존한 채 별도 작업본에서 최신 main을 준비합니다.

## 2. 빌드와 WDS 환경 점검

저장소 폴더에서 실행합니다.

```powershell
dotnet build EduStream.sln
dotnet test EduStream.sln --no-build
powershell.exe -NoProfile -STA -ExecutionPolicy Bypass -File scripts/Test-RdpSharingEnvironment.ps1
```

- 빌드가 실패하면 앱 실행 전에 오류를 해결합니다.
- 일반 테스트의 WDS 3항목 건너뜀은 환경 의존 검증을 분리한 결과입니다. RDP 미지원/성공을 의미하지 않습니다.
- 환경 스크립트에서 활성화·공유 Open·초대 생성·회수·Close의 PASS를 확인합니다.
- 이 점검은 학생 PC의 실제 연결 성공이나 화면 표시까지 보장하지 않습니다.
- ProgID 검색 실패만으로 미지원으로 판단하지 않습니다. 구현은 CLSID로 활성화합니다.
- COM 활성화 오류가 나면 OS/아키텍처·오류 형식을 기록해 공유합니다. 출처 불명 DLL 설치나 레지스트리 변경으로 우회하지 않습니다.

## 3. 교수자 앱 시작

첫 PowerShell 창:

```powershell
dotnet run --project src/EduStream.Server/EduStream.Server.csproj --no-build
```

1. EduStream Server 창에서 세션 이름을 확인합니다. 기본값은 `Capstone Live Class`입니다.
2. 포트 `5000` 확인 → **세션 열기** 클릭.
3. 아래 **실시간 RDP 화면 공유 (WDS)** 영역에서 **WDS 공유 시작** 클릭.
4. 상태가 `WDS 공유 중 · 보기 전용 · 최대 학생 2명`으로 바뀌는지 확인합니다.
5. 학생이 참가하고 RDP 초대를 요청할 때까지 기다립니다.

WDS는 현재 교수자 데스크톱을 공유합니다. 개인정보/비밀번호/사적인 창은 먼저 닫고 발표용 창을 준비합니다. Windows 원격 데스크톱 로그인 비밀번호나 RDP 서버 주소를 이 화면에 입력하는 방식이 아닙니다.

## 4. 학생 1·2 앱 시작 및 접속

학생 PC마다 별도 PowerShell 창에서 실행합니다. 한 PC 자동/간이 점검이라면 창을 두 개 열어 같은 명령을 각각 실행합니다.

```powershell
dotnet run --project src/EduStream.Client/EduStream.Client.csproj --no-build
```

1. 오른쪽 **설정** 탭 클릭.
2. 표시 이름을 첫 학생 `Student01`, 둘째 학생 `Student02`로 다르게 입력합니다.
3. **호스트**: 같은 PC 점검은 `127.0.0.1`, 다른 학생 PC에서는 교수자 PC의 로컬 IPv4 주소를 입력합니다.
4. **포트**: 교수자와 같은 `5000` 입력 → **세션 참여** 클릭.
5. 세션 참가 성공 후 RDP 초대를 자동 요청합니다. **설정 → RDP**의 초대 수신/비밀번호 입력 안내를 확인합니다.
6. 교수자는 자신의 앱에서 **초대 비밀번호 전달 대상** 목록의 해당 학생을 선택 → **선택 학생의 초대 비밀번호 복사** 클릭.
7. 복사한 값을 해당 학생에게 별도 비공개 채널로 전달합니다. EduStream 공용 채팅, 공유 중인 화면, 공개 문서에 붙여 넣지 않습니다. 클립보드 기록/동기화에 비밀정보가 남지 않도록 주의합니다.
8. 학생은 **교수자에게 별도로 받은 초대 비밀번호** 입력란에 붙여 넣기 → **RDP 연결** 클릭.
9. 상태가 `RDP: Connected`인지 확인합니다. 둘째 학생도 자기 초대 비밀번호로 동일하게 진행합니다.
10. 두 학생에게 실제 강의 화면이 보이는지 확인하고 교수자 창 이동/스크롤/슬라이드 전환이 두 화면에 반영되는지 직접 비교합니다.

초대 비밀번호는 학생별로 다르고 발급 후 5분 이내 사용합니다. Windows 계정 비밀번호가 아닙니다. 만료/공유 재시작/재접속 시 예전 비밀번호를 재사용하지 않습니다. 이미 연결된 학생을 5분마다 끊는 정책은 아닙니다.

교수자보다 먼저 참가한 학생은 WDS 시작 후 **RDP 재접속**을 눌러 새 초대를 요청해야 합니다. 이 버튼은 즉시 연결 완료 버튼이 아니라 **새 초대 요청**입니다.

## 5. 파일과 채팅 병행

1. 두 학생의 RDP 화면이 연결된 상태에서 교수자 **파일 선택** → 샘플 파일 선택 → **선택 파일 전송** 클릭. 간단한 점검은 **샘플 파일 전송**으로 진행합니다.
2. 교수자 전송 완료만으로 학생 저장 완료를 단정하지 않습니다. 두 학생 각각 **파일** 탭에서 저장 완료와 파일명을 확인합니다.
3. 학생 파일 저장 기본 위치는 `%TEMP%\EduStreamClient\<클라이언트 프로세스 ID>\`입니다. **로그** 탭의 저장 완료 경로로 실제 파일을 확인합니다.
4. PowerShell에서 `Get-FileHash -Algorithm SHA256 -LiteralPath '실제 저장 파일 경로'`를 실행해 교수자 원본과 비교합니다.
5. **채팅** 탭에서 학생 1·2와 교수자가 각각 메시지를 보내고 상대 화면 수신을 확인합니다.
6. 파일 전송 동안에도 교수자 화면을 이동/스크롤해 RDP가 멈추지 않는지 확인합니다.

파일 저장은 완료됐는데 상단이 67% 등 이전 진행률에 머무는 알림 전이는 #41에서 보완했습니다. 검수에서는 파일 탭, 실제 파일, 상단 알림을 함께 확인합니다.

## 6. 종료·재접속

- **학생 한 명 종료:** 해당 학생의 설정 → 연결 종료. 다른 학생의 RDP/파일/채팅은 유지되는지 확인합니다.
- **학생 재참여:** 세션 참여 → 새 초대 비밀번호 전달 → RDP 연결.
- **RDP만 재접속:** 설정 → RDP 재접속 → 교수자에게 새 비밀번호 전달받기 → 입력 → RDP 연결.
- **교수자 공유 중지:** WDS 공유 중지. RDP 두 연결이 종료되지만 강의 TCP 세션 자체는 남습니다.
- **교수자 공유 재시작:** WDS 공유 시작. 학생은 각각 RDP 재접속으로 새 초대를 요청합니다.
- **강의 전체 종료:** 세션 닫기. 초대 회수·RDP 공유 종료·TCP 세션 종료를 확인합니다.
- **앱 창 닫기:** 종료 처리가 끝날 때까지 기다립니다. 창을 여러 번 강제 종료하지 않습니다.

## 7. 보조 기능의 의미

- 교수자 **보조 PNG 1회 전송 / 보조 PNG 시작 / 보조 PNG 중지**는 이미지 전송 진단입니다. WDS 공유 중에는 PNG 시작을 제한합니다.
- 학생 설정의 **화면 수신 테스트 / 파일 수신 테스트**는 개발자 테스트입니다. 실제 교수자 송수신의 증빙으로 사용하지 않습니다.
- PNG 프레임 번호/갱신 시각을 RDP 프레임 속도로 읽지 않습니다. RDP 연결 상태는 설정 탭에서 확인합니다.
- RDP Connected는 실제 연결 이벤트 근거이지만, 모든 픽셀이 정확히 표시되거나 지연 기준을 충족했다는 보장은 아닙니다.

## 8. 연결 실패 점검

1. 교수자 세션 열기와 WDS 공유 시작을 모두 했는지 확인합니다.
2. 학생 이름 중복, 호스트 IPv4, 강의 TCP 포트를 확인합니다. 다른 PC에서 `127.0.0.1`을 쓰지 않습니다.
3. 학생 세션만 연결되고 RDP가 안 되면 새 초대·비밀번호·만료와 WDS 지원 상태를 점검합니다.
4. WDS 통신 포트를 강의 TCP 5000 또는 일반 원격 데스크톱 3389로 고정 가정하지 않습니다. 초대 기반 실제 연결 환경에 맞춰 점검해야 합니다.
5. Windows 방화벽을 전체 해제하거나 공유기를 인터넷에 개방하지 않습니다. 앱/네트워크 허용이 필요하면 관리자와 해당 신뢰 네트워크 범위만 확인합니다.
6. 실패 시 커밋, OS/아키텍처, 동일 PC/다중 PC 여부, 세션 연결 여부, RDP 상태/실패 이유, 시간만 기록합니다. 비밀번호/초대 문자열/전체 패킷 JSON은 공유하지 않습니다.

## 9. 개발자 실제 WDS 선택 검증

공유 가능한 테스트 데스크톱에서만 수행합니다. 테스트가 실제 WDS 세션과 두 viewer를 생성하며 테스트용 공유는 종료 시 정리합니다.

```powershell
$env:EDUSTREAM_WDS_SMOKE = '1'
try {
    dotnet test EduStream.sln --no-build --filter 'FullyQualifiedName~RdpSharingContractTests|FullyQualifiedName~RdpViewerIntegrationTests|FullyQualifiedName~ServerRdpIntegrationTests' --blame-hang-timeout 45s
}
finally {
    Remove-Item Env:EDUSTREAM_WDS_SMOKE -ErrorAction SilentlyContinue
}
```

현재 현 PC 결과와 미완료 항목은 [통합 검증 기록](./SEPTEMBER_RDP_INTEGRATION.md)을 확인합니다. 다중 PC 실시간 표시/지연 → 15분 병행 → 전체 시연 2회 순서로 기록한 뒤 수동 인수를 완료합니다.
