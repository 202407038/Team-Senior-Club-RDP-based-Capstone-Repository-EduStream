# 현재 상태와 로드맵

이 문서는 작업자가 현재 구현 상태와 이번 주 목표를 빠르게 확인하기 위한 공용 작업 문서입니다.

기준 자료:

- [졸작 중간발표 자료](../reference/presentations/졸작중간발표.pptx)
- [전체 주차별 로드맵](./FULL_WEEKLY_ROADMAP.md)

## 운영 규칙

- 월간 로드맵은 현재 달과 다음 달까지만 유지합니다.
- 전체 주차별 원본 계획은 `FULL_WEEKLY_ROADMAP.md`에서 관리합니다.
- 주차별 계획은 일차별로 나누지 않고, 팀 목표치와 담당별 목표치만 관리합니다.
- 완료된 항목은 문장 끝에 `----- %완료%`를 붙여 표시합니다.
- 지난 주차에서 끝내지 못한 항목은 다음 주차 목표에 포함합니다.
- 매주 수요일 기준으로 main 반영 상태, PR 상태, 빌드/테스트 결과를 갱신합니다.
- PR은 역할별로 분리하고, main 반영 전 `dotnet build EduStream.sln`과 `dotnet test EduStream.sln --no-build` 결과를 확인합니다.

## 월간 로드맵

현재 6월 4주차에서 7월 작업으로 넘어가는 구간이므로, 이 문서에는 6월 마감 기준과 다음 달인 7월 목표를 함께 표시합니다.

### 6월 목표: 기반 구축과 핵심 엔진 진입 준비

- 공통 패킷 / 직렬화 / 검증 규칙 기준선 확정
- 세션 관리 기초 흐름 main 반영 상태 확인
- 기초 UI와 로깅 시스템 main 반영 상태 확인
- 역할별 담당 범위와 PR 기준선 정리
- 7월 화면 캡처 엔진 작업에 필요한 연결 지점 확인

### 7월 목표: 화면 캡처 엔진과 송수신 흐름 고도화

- 화면 캡처 엔진과 화면 송신 흐름을 실제 사용 흐름에 연결
- TCP 기반 다중 클라이언트 송수신 안정화
- 화면 / 파일 / 채팅 패킷 흐름을 같은 세션 기준으로 검증
- 송수신 실패 시 fallback / 로그 / 상태 메시지 기준 구현
- 8월 상태 관리와 중간 통합 테스트에 들어갈 수 있는 기준선 확보

- 7월 송수신 고도화 작업에 필요한 버튼, 상태 문구, 오류 표시 정리

### 7월 1주차

#### 팀 목표치

- 화면, 파일, 채팅 패킷이 같은 세션에서 흘러가는 기준선 확인
- 화면 캡처 실패, 파일 실패, 채팅 실패가 서로 다른 상태와 로그로 남도록 기준 정리
- 서버와 클라이언트 실행 흐름을 1회 이상 수동 검증
- main 기준 build/test 결과 기록

#### 담당별 목표치

##### 1. 공통 코어 / 프로토콜

- 화면 / 파일 / 채팅 payload 길이와 `DataLength` 기준을 공통 검증 규칙으로 정리
- `AckCode`, `ErrorCode`, `PacketType` 누락 / 오용 테스트 추가

##### 2. 서버 세션 / 네트워크

- 화면 송신 중 disconnect가 발생해도 세션 정리가 되는지 확인
- heartbeat timeout과 화면 송신 루프가 같은 클라이언트를 중복 제거하지 않는지 확인

##### 3. 화면 송신

- 화면 캡처 실패 시 fallback 프레임과 정상 프레임이 구분되도록 로그와 상태 확인
- 화면 공유 시작 / 중지 상태 전환이 서버 UI에 반영되는지 확인

##### 4. 파일 전송

- 파일 전송 실패 메시지가 화면 / 세션 상태와 섞이지 않도록 결과 모델과 로그 확인
- 파일 전송 완료 후 같은 세션에서 추가 전송 가능한지 테스트

##### 5. 클라이언트 UI / 수신

- 화면, 파일, 채팅 상태 문구가 서로 덮어쓰지 않는지 UI 기준 정리
- 오류 메시지가 사용자에게 보이는 문구로 정리되어 있는지 확인

#### 완료 기준

- 최소 1개 이상의 실제 코드 PR과 관련 테스트 PR이 main에 반영됩니다.
- 서버와 클라이언트 실행 후 join, 채팅, 파일 샘플 전송, 화면 프레임 전송을 확인합니다.
- 실패 로그가 `[Screen]`, `[File]`, `[Chat]`, `[Session]`, `[Tcp]`처럼 구분됩니다.

- 다중 클라이언트 기준 화면 / 파일 송수신 흐름 검증
- 송신 실패 클라이언트 제거 후 나머지 클라이언트 유지 확인
- UI 상태 표시와 실제 송수신 결과 연결 보강
- main 기준 build/test 결과 기록

#### 담당별 목표치

##### 1. 공통 코어 / 프로토콜

- 잘못된 `PacketType`, `AckCode`, `ErrorCode` 처리 기준을 공통 유틸이나 테스트로 고정 ----- %완료%
- 화면 / 파일 패킷 실패 응답 모델이 `Core` 기준으로 재사용 가능한지 확인 ----- %완료%

##### 2. 서버 세션 / 네트워크

- 다중 클라이언트 송신 중 실패 클라이언트 제거 흐름 구현 또는 테스트
- 서버 로그에 `clientId`, `sessionId`, 실패 사유가 남도록 보강

##### 3. 화면 송신

- 다중 클라이언트 기준 화면 프레임 송신 흐름 검증
- 화면 공유 중지 요청 후 루프 종료와 상태 메시지가 맞는지 확인

##### 4. 파일 전송

- 파일 패킷 브로드캐스트가 다중 수신자 기준으로 저장되는지 테스트 ----- %완료%
- 파일 실패 후 재전송 가능 여부와 임시 파일 정리 여부 검증 ----- %완료%
- 파일 payload 길이 불일치 실패 처리 검증 ----- %완료%

##### 5. 클라이언트 UI / 수신

- 화면 수신 상태와 파일 수신 상태를 독립적으로 표시
- disconnect / reconnect 상황에서 UI 상태 문구가 초기화되는지 확인

#### 완료 기준

- 수강생 2명 이상 기준 세션 유지 테스트가 통과합니다.
- 파일 전송 실패, 재전송, 완료 상태가 테스트와 UI 흐름에서 확인됩니다.
- 1번 / 4번 작업은 테스트만으로 끝내지 않고 실제 검증 규칙 또는 서비스 흐름을 포함합니다.

- 세션 접속 후 화면 공유, 파일 전송, 채팅을 같은 실행 흐름에서 연결
- 기능별 실패 상황을 실제 시나리오로 재현하고 수정

- main 기준 build/test 결과 기록

#### 담당별 목표치

##### 1. 공통 코어 / 프로토콜

- 화면 / 파일 / 채팅 공통 상태 모델 초안 작성
- 통합 시나리오에서 필요한 공통 응답 모델 보강

##### 2. 서버 세션 / 네트워크

- 교수자 1명, 수강생 2명 이상 기준 통합 실행 흐름 검증
- 통합 실행 중 서버 예외가 전체 세션을 끊지 않는지 확인

##### 3. 화면 송신

- 화면 공유 시작, 송신 중, 중지 흐름을 통합 시나리오에 연결
- 화면 송신 중 파일 전송과 채팅이 끊기지 않는지 확인

##### 4. 파일 전송

- 화면 공유 중 파일 선택, 전송, 수신 완료 흐름 검증
- 파일 전송 완료 메시지가 채팅 / 화면 상태와 충돌하지 않는지 확인

##### 5. 클라이언트 UI / 수신

- 세션, 채팅, 파일, 화면 상태가 한 화면에서 읽히도록 UI 점검
- 상태 문구 우선순위와 갱신 기준 정리

#### 완료 기준

- 통합 시나리오 체크리스트가 만들어지고, 최소 1회 수동 검증 결과가 문서에 기록됩니다.
- 화면 공유 중 파일 전송과 채팅을 순차 실행해도 앱이 멈추지 않습니다.
