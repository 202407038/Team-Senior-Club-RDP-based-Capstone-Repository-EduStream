# 학생 화면 겹침 및 접기 처리

## 원인과 수정

학생 수신기는 WPF 안의 네이티브 창입니다. WPF의 접기·스크롤 영역 제한만으로는 네이티브 창의 표시 영역까지 제한되지 않습니다. 투명 배경에서는 이전 목록이 WinForms 배경 이미지로 복사되어 영상 여백에 남는 문제도 있었습니다.

- 표시 가능한 상위 스크롤 영역과 교차하는 네이티브 창 영역을 적용합니다. 접히거나 화면 밖으로 나가면 빈 영역으로 제한합니다.
- 호스트 배경을 검정으로 지정해 이전 목록 이미지가 수신 화면 뒤에 남지 않도록 합니다.
- 단순 접기에는 연결을 유지하고, 창에서 제거된 이전 템플릿은 정리합니다. 이벤트 해제에는 실제 구독했던 모델을 사용합니다.
- WDS 초대·송수신 프로토콜 및 원격 입력 엔진은 변경하지 않습니다.

## 확인 범위

- 실제 학생 화면을 수신한 상태에서 개별 접기·펼치기, 연속 클릭 및 스크롤 후 겹침이 사라지는 것을 확인했습니다. 같은 뷰·수신기와 연결 유지 상태도 확인했습니다.
- `StudentScreenNativeClipTests`는 비활성 오프스크린 창에서 실제 HWND를 사용합니다. 접기·펼치기 50회, 스크롤 경계, 창 크기 변경, 재배치를 검사합니다. 이 자동 검사는 실제 WDS 연결 검사를 대체하지 않습니다.
- 기존 재시도·뷰어 해제·잘못된 초대·공유 철회 관련 선별 회귀를 함께 확인합니다.
- PR 정리 중 오프스크린 검사의 디스패처 대기에서 30초 시간 초과가 재현되어 검사 대기 방식을 보완했습니다. WPF 디스패처를 명시하고 짧은 비동기 대기 전후 배치를 갱신하며 기존 판정은 유지합니다. 보완 후 단독 반복 3회 통과를 확인했습니다.
- 양방향 공유·원격 제어·동시 접속의 기존 사용자 확인 결과는 유지합니다. 이번 변경에서 다중 PC 전체 인수를 다시 수행했다고 표기하지 않습니다.

## 캡처와 배포 경계

확인용 실행기에서만 캡처 차단을 잠시 해제해 겹침을 확인했고, 이후 허용 파일을 제거하고 차단 값 `0x11` 복원을 확인했습니다. 제품의 캡처 차단 코드는 변경하지 않았습니다. 확인용 실행기·실제 수신 캡처·개인정보는 저장소에 포함하지 않습니다. 이번 PR 단계에서 ZIP은 갱신하지 않습니다.
