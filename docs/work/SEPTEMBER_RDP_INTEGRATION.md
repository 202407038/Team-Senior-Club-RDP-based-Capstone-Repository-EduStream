## 2. 검증 결과

| 검증 | 결과 | 의미 |
|---|---|---|
| dotnet build EduStream.sln | 경고 0 / 오류 0 | WPF 및 테스트 컴파일 |
| #39+#40 일반 전체 반복 | 184 통과 / WDS 3항목 건너뜀, 2회 연속 | TCP 수정 포함 통합 회귀 |
| #41 일반 전체 | 186 통과 / WDS 3항목 건너뜀 | 파일 상태 회귀 2건 추가 |
| 실제 WDS 포함 선택 실행 | 11/11 통과 | 실제 COM 5개 데이터 케이스와 계약/상태 대역 6개 |
| TCP 종료 회귀 선택 실행 | 32/32 통과 (#40 시점) | 세션/다중 참가/잠금 종료 |

일반 실행의 건너뜀은 WDS 환경 선택 테스트를 뜻하며 실패도, 실제 WDS 성공도 아닙니다. 전체 통과율을 프로젝트 진척률로 환산하지 않습니다.

실제 WDS 선택 명령은 [실행 가이드 9절](./RUN_GUIDE.md#9-개발자-실제-wds-선택-검증)에 있습니다. 현 PC의 실제 COM/STA 이벤트를 사용하며 대역 테스트만으로 RDP 성공을 기록하지 않았습니다.

확인한 사항:

- 동일 RDPSession에 실제 RDPViewer 두 개 연결 및 Connected 이벤트.
- 초대 기반 보기 전용 승인, 한 학생 회수 후 다른 학생 연결 유지, 같은 학생 새 초대 재접속.
- 교수자 ViewModel의 세션 열기 → WDS 시작 → TCP 학생 참가 → 초대 요청 → 별도 비밀번호 조회 → 실제 viewer 연결.
- 실제 WDS를 유지한 1KB·8MB 파일 저장과 원본 바이트 일치, 채팅 수신.
- checksum 오류 주입 후 기존 파일 보존, 다음 전송 복구, RDP 연결 유지. PNG 패킷 수 0.
- WDS 중지 후 두 viewer 종료, 강의 세션 유지, 새 SharingId/비밀번호로 재시작.
- 시작 실패 상태 및 시작 도중 앱 종료 순서(대역), 파일 완료/재시도 알림과 타 기능 오류 보존(상태 로직).

## 3. 종료 경합 기록

기존 전체 실행에서 세션 RDP 재접속 테스트 대기를 관찰했고, #39 재검증에서는 SessionMultiClientTests.ThreeClientsJoin_ShouldReportParticipantCountThree 실행 중 45초 비활성 제한으로 중단됐습니다. 테스트 호스트가 자동 생성한 덤프는 로컬 무시 산출물이며 PR에 포함하지 않았습니다.

별도 결정적 재현에서 송신 잠금을 점유 → 후속 송신 대기 → 연결 Dispose → 선행 송신의 Release 순서로 SemaphoreSlim 폐기 오류를 확인했습니다. #40은 잠금이 남은 작업보다 먼저 폐기되지 않게 수정하고 소켓 종료로 송신을 해제합니다. 서버의 단일/16개 대기 및 클라이언트 종료/중복 Dispose를 회귀 테스트로 고정했습니다.

수정 후 전체 반복은 통과했습니다. 다만 과거 모든 대기의 유일한 원인을 확정한 것은 아닙니다. 4주차 장시간/강제 종료 검증에서 재발 여부를 계속 확인합니다.

## 4. 아직 확인하지 않은 범위

- 실제 교수자 PC 1대 + 학생 PC 2대의 LAN/방화벽 통과.
- 화면 픽셀 내용, 창 이동/스크롤/슬라이드 전환의 실제 수신·지연 측정.
- 최종 WPF 전체 화면의 수동 클릭 검수 및 다중 모니터 시연 배치.
- 저장 권한/잠금 오류의 사용자 UI와 다중 PC 해시 비교.
- 15분 이상 공유·파일·채팅 병행, 케이블/네트워크 단절·복구.
- 처음부터 끝까지 전체 시연 2회, 새 RDP 캡처/발표자료 반영.

같은 PC의 실제 COM 연결은 다중 PC 검증을 대신하지 않습니다. 기존 PNG 캡처를 RDP 영상 수신의 증빙으로 재사용하지 않습니다. 현재는 3주차 구현/자동 통합 반영이며 수동 인수와 4~5주차는 남아 있습니다.
