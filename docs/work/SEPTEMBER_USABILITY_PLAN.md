# 9월 UI·편의성·RDP 피드백 반영 계획

작성일: 2026-09-18. 기준 코드: `96c8bae` (#44). 상태: **피드백·일정 계획 / 신규 기능 미구현**. 팀장은 재검토 후 이번 문서 변경의 커밋·푸시·PR·머지를 승인했습니다. 기능 구현·배포와는 구분합니다.

## 1. 일정 판단과 현재 상태

- 팀장은 9/17 기본 기능에 문제가 없음을 확인했다고 전달했습니다. 이전 화면 미표시를 지속 결함으로 취급하지 않지만, 이 확인을 다중 PC·지연 측정·15분 실행·전체 시연 2회의 상세 검증 기록으로 확대하지 않습니다.
- #43 설치형과 #44 실행용 ZIP은 기존 배포 완료 이력입니다. 이번 편의 개선이 그 배포판에 들어갔다는 뜻이 아닙니다.
- **최종 11/1 목표 유지 가능성을 전제로 한 조건부 계획**입니다. 9/20 설계/기술 확인, 9/27 1차 통합, 10/4 개선판 인수 후 10/5 동결 진입을 목표로 합니다. 달성 보장은 아닙니다.
- 9/21~10/4의 두 주에 역할별 병행 구현과 주말 통합을 배치합니다. 실제 가용 시간·작업 속도는 미확인이므로 인일 추정이나 퍼센트를 확정하지 않습니다. 팀장 혼자 전 역할 구현/보완까지 한다는 전제로는 이 일정을 보장하지 않습니다.
- 기존 4~5주차 회귀/시연에 개선 구현이 추가돼 여유가 줄었습니다. 특히 방 인증·자동 재연결, 파일 요청 전송, ActiveX 확대축소/다중 모니터가 일정 위험입니다.
- 10/4 미달이면 QA·보고서 기간을 임의로 줄이지 않고 원인과 남은 범위를 보고합니다. 팀장이 일부 항목 후순위 전환 또는 날짜 조정을 결정하기 전에는 요구사항을 임의로 삭제하지 않습니다.

## 3. 계약 변경과 보안 경계

현재 구현 사실은 [RDP 구현 계약](./RDP_IMPLEMENTATION_CONTRACT.md)을 따릅니다. 아래는 변경 목표이지 이미 확정·구현된 새 프로토콜이 아닙니다.

- 사용자 방 비밀번호와 내부 WDS 초대 인증을 구분합니다. 방 비밀번호가 같아도 학생별 참가 신원/연결 ID/회수는 유지합니다.
- 무비밀번호 방은 사용자가 선택하는 참가 정책입니다. 내부 초대 검증 제거·학생 제어 허용·인터넷 공개를 의미하지 않습니다. 참가 가능한 네트워크 범위를 UI와 문서로 안내합니다.
- 기존 평문 TCP에 방 비밀번호나 WDS 비밀을 단순 추가하는 식으로 편의를 구현하지 않습니다. 1번은 9/20까지 보호된 인증/초대 전달 또는 안전한 인증 방식과 위협 경계를 검토하고, 2·5번이 사용할 계약·실패 응답·호환 정책을 확정합니다. 안전한 방식이 정해지지 않으면 F04/F05를 일정 위험으로 보고하며 검증을 생략하지 않습니다.
- 방 비밀번호는 세션 생성 시 설정/미설정으로 한정하는 최소 범위를 제안합니다. 실행 중 비밀번호 변경·영구 저장은 이번 필수에 포함하지 않습니다. 재시작한 앱의 새 참가와 같은 세션 내 화면 재연결을 구분합니다.
- 공유 중지 후 RDPSession을 다시 열 때 이전 네이티브 연결이 그대로 남는다고 보장하지 않습니다. 사용자가 기대하는 것은 **강의 세션 유지 + 새 초대로 자동 복귀**이며, 내부 SharingId/ConnectionId는 현재 공유에 맞게 갱신합니다. 퇴장/초대 회수 등 종료 사유를 구분해야 합니다.
- 파일명 대신 서버가 발급한 파일 식별자로 요청합니다. 승인된 참가자만 등록된 파일을 요청하고 클라이언트가 임의 서버 경로를 지정할 수 없게 합니다. 서버 목록 등록과 학생의 실제 저장 완료를 구분합니다.
- 다운로드 폴더는 사용자의 실제 Windows 다운로드 위치를 사용합니다. 기존 파일을 무단 덮어쓰지 않고 수신 파일을 자동 실행하지 않습니다.
- F02 확대축소는 PNG Viewbox가 아니라 실제 WDS ActiveX에서 검증해야 합니다. 기술 확인 실패를 이미지 송신으로 바꿔 완료 처리하지 않습니다.

9/20 산출물은 1번의 변경 계약/테스트 예시와 각 담당의 최소 기술 검증입니다. 그 전에는 각자 패킷 번호·비밀번호 형식·재연결 의미를 다르게 만들지 않습니다. 다른 역할이 아직 구현되지 않으면 승인 계약의 테스트 대역으로 독립 작업합니다.

## 5. 후순위 추가 항목 (미삭제, 일정 미배정)

- B01: 교수자 미리보기 위 판서/가벼운 그림판.
- B02: 교수자 공지를 학생 화면 상단에 잠시 표시.
- B03: 학생의 명시적 허용에 따른 학생 화면 공유·교수자 모니터링.
- B04: 학생이 허용한 동안 교수자가 선택 학생을 원격 조작하는 기능. 학생→교수자/타 학생 제어는 제외.
- B05: 동시 참가 인원 확대 및 성능 한계 측정. 현재 코드의 WDS 활성 초대 제한은 2명이며 대규모 사용을 보장하지 않습니다.

추가 항목은 이번 11/1 완료율의 필수 분모에 넣지 않습니다. 나중에 목표 인원, 동시에 볼 학생 수, 동의·표시·즉시 중단 정책을 확정하고 별도 일정 승인 후 진행합니다.

## 6. 검증·문서·게시 원칙

- 일반 전체 테스트 186 통과/선택 WDS 3항목 건너뜀과 실제 WDS 11/11은 기존 기록입니다. 변경 후 다시 실행해 새 결과를 기록해야 합니다.
- 코드 버전·OS·모니터/DPI·참가 PC/학생 수·실행 시간·입력 순서·실제 결과를 기록합니다. 비밀번호와 초대 문자열은 기록/캡처하지 않습니다.
- 기본 기능 확인, 코드 구현, 자동 검증, 수동 인수, GitHub 반영을 별도 표시합니다. 이번 일정 문서 반영으로 기능 완료율을 임의로 올리지 않습니다.
- 기존 개발 방식대로 역할/목적별 변경을 분리하고, 승인 후 커밋할 때 구현·테스트·문서를 구분합니다. 기능 브랜치에 전체 로드맵을 섞지 않습니다.
- 이번 승인 범위는 피드백·로드맵 문서의 검토 및 병합입니다. 후속 기능 구현의 커밋·푸시·PR·머지와 Releases 업로드는 별도 지시를 따릅니다.
- [현재 로드맵](./STATUS_AND_ROADMAP.md), [전체 일정](./FULL_WEEKLY_ROADMAP.md)은 동일한 주차 일정을 사용합니다. 실행 가이드·기존 RDP 계약·발표자료는 실제 기능 변경/검증 뒤 동기화합니다.

## 8. 재검토 결과와 진행 조건

- 원문 25항목 모두 우선 범위 또는 후순위 목록에 연결했습니다. 3번의 미리보기와 판서를 분리해 판서를 조용히 누락하지 않았습니다.
- 9/18~20은 확정 구현 마감이 아니라 위험 확인 단계입니다. 방 인증 보호 방식/호환 정책, ActiveX 확대축소, 다중 모니터 좌표, 같은 PC 실행 제한 경계를 확정할 근거가 부족하면 해당 담당이 결과와 지연 영향을 보고합니다.
- 9/25 및 10/2까지 역할별 검토본을 준비하고, 9/26~27 및 10/3~4는 통합·재검증에 남깁니다. 10/4 마지막 날까지 새 기능 구현을 계속하는 계획이 아닙니다.
- 기존 회귀에서 네트워크 단절·heartbeat timeout·강제 종료/재접속, 학생 한 명 실패 시 다른 학생 유지, 초대 회수/보기 전용, 자원 해제/송신 종료 경합, 파일 checksum·권한·잠금 오류는 유지합니다. 편의 개선 때문에 이 검증들을 삭제하지 않습니다.
- 1번이 계약과 교수자 UI, 4번 파일까지 맡으므로 팀장 병목을 점검합니다. 2·3·5번은 서비스/API·학생 UI 및 관련 단독 검증을 자기 책임으로 제출하고 팀장이 전부 재작성할 것으로 가정하지 않습니다.
- 일정은 기존 11/1 목표 안에 배치됐지만 자원/기술 검증 전의 조건부 전망입니다. 9/20 기술 확인 실패 또는 9/27 1차 통합 미달이면 10/4 완료 가능성을 다시 산정합니다. 테스트 생략이나 보안 검사 제거로 날짜만 맞추지 않습니다.
