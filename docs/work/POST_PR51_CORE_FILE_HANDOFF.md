## 2. 2·3번이 사용할 역방향 계약

- `Core/Collaboration/ReverseRdpInvitationNotice.cs`: #51의 필드를 보존한 공통 계약입니다. Server의 `ReverseInvitationWire.ToContract()` / `FromContract()`가 기존 엔진과 변환합니다. 학생 앱이 DTO를 읽기 위해 Server 프로젝트를 참조할 필요가 없습니다.

- codec 성공은 구조 검사뿐입니다. 신규 수신부는 접속 전에 `ValidateForSharing(sessionId, sharingId, professorId, connectionId, studentId, now)`를 호출합니다. 기대 값은 수신 JSON을 복사하지 말고 현재 인증 연결/참가자 레지스트리 및 학생별 현재 공유 상태에서 얻습니다. 기존 `ValidateForConnection`은 호환용이며 공유 재시작 전 초대까지 걸러 주지는 않습니다.

- `ViewOnly=false`는 즉시 원격 제어 허용이 아닙니다. `HostGrantedInteractive` 초대도 최초에는 보기 전용이고, 권한 확인 뒤 3번 Grant/Revoke를 호출합니다.

1. 3번 학생 호스트가 #51 엔진으로 초대를 생성합니다.
2. 2번이 현재 인증 연결/학생/공유와 대조해 초대와 비밀을 교수자에게 전달합니다.
3. 수신 측이 codec 구조 검사 → 현재 연결·공유 세대 대조 → 비밀 대조 후 실제 viewer 연결을 시작합니다.
4. 연결/실패/끊김 이벤트로 상태를 확정합니다. 메시지를 보냈다는 이유로 연결 성공을 반환하지 않습니다.
5. 제어 정책은 2번, WDS Grant/Revoke와 실제 viewer 입력 동작은 3번, 학생 선택/표시/조작 UI는 5번이 담당합니다.

## 3. 판서 계약과 표시 연결

- 기존 `AnnotationStrokeWire` 및 `AnnotationLayerWire` JSON을 `AnnotationTransportNotice(SessionId, SharingId, ConnectionId, Sequence, PayloadJson)`로 감쌉니다. 엔진 JSON을 새 형식으로 재작성할 필요가 없습니다.
- `PayloadJson`은 UTF-8 1MiB, 레이어 최대 4096스트로크, 스트로크 최대 4096좌표, 굵기 1~256입니다. 전체 codec 봉투 상한은 기존 2MiB입니다. JSON 이스케이프 때문에 원문이 1MiB보다 작아도 봉투 2MiB 제한에 걸릴 수 있습니다. 초과를 조용히 누락하지 말고 실패로 표시합니다.
- 중복 JSON 속성, 잘못된 도구/좌표/색, 중복 스트로크 ID, 숨김 레이어의 비어 있지 않은 표시 목록을 거부합니다.
- wire 도구는 `Pen/Eraser/Line/Rectangle/Circle`, 좌표는 최소 2개입니다. UI 공통 도구 `Ellipse`는 기존 엔진이 `Circle`로 내보냅니다. 실제 엔진이 표시하지 못하는 `Highlighter/Arrow/Text`, wire의 `Ellipse`, 한 점 스트로크는 거부합니다. UI 도구를 새로 추가한 것이 아니라 실제 제공 엔진과 공통 검사를 맞춘 수정입니다.
- 2번은 `ValidateForSender(인증된 교수자 연결, 현재 sharingId, 마지막 적용 sequence)`로 대조합니다. 학생발 판서·이전 연결·다른 공유·중복/역순 번호는 적용하지 않습니다.
- `Sequence`는 스트로크/스냅샷을 합친 순서입니다. `ContentRevision`과 동일한 카운터가 아닙니다. 수신 레이어 적용을 await한 뒤 마지막 적용 번호를 갱신합니다. 재연결 복원 스냅샷 송신과 번호 수명은 2번 라우터가 관리합니다.
- 3번의 `BindTransmission(engine, onPayloadReady)`가 두 JSON 종류를 제공합니다. 2번이 봉투로 전달하고, 수신의 `ReceiveRemoteStrokeJsonAsync(json)`를 await합니다. 전체 삭제·숨김·재표시·지우개·Undo 스냅샷도 전달해야 합니다.
- 5번은 툴바/실제 포인터/오버레이 창을 연결합니다. 버튼 활성화만으로 완료하지 않습니다. 학생 측 렌더러 재사용/배치는 3번과 협의하며 학생 앱이 Server 실행 프로젝트에 직접 의존하도록 우회하지 않습니다.

따라서 1·4번 독립 준비는 먼저 올릴 수 있지만, **모든 담당 결과를 반영한 통합 검수까지 지금 완료할 수는 없습니다.** 후속 소비에서 계약 수정이 필요하면 1번이 대응하고, 각 담당 구현 책임을 대신 완료로 표시하지 않습니다.

### 4.1 2번: 이미 있는 서비스와 남은 연결

- 제공됨: 참가자/권한 정책, IP·선택 방 비밀번호를 통한 보호 참가, 재참가 토큰, 파일 요청 라우팅, 기존 정방향 WDS 초대/비밀 자동 전달. 이 기능들을 새로 만들라는 요청이 아닙니다.
- 남은 구현: Kind 15·16 학생→교수자 전달과 Kind 17 교수자→학생 전달/수신 분기. 인증된 발신자·대상과 Guid/문자열 신원을 한 규칙으로 매핑하고, 현재 세션·학생별 공유 세대·연결·만료를 대조합니다. 초대 비밀은 해당 교수자 연결에만 전달합니다.
- 남은 구현: 판서 적용 순서/재접속 스냅샷, 공유 재시작 시 이전 초대·비밀 폐기, 구버전 상대의 지원 여부/실패 처리. `ReverseWdsRemoteInputGate`를 실제 학생 호스트의 Grant/Revoke에 연결하고 단일 제어 대상·학생 허용 철회·이탈/종료 시 회수 정책을 적용합니다.
- 검증: 정상 전달뿐 아니라 이전 공유/연결·다른 학생·만료·중복/역순·권한 회수·대상 변경을 거부하는 서비스 통합 테스트를 제출합니다. codec 통과나 전송 요청 성공을 실제 연결/입력 성공으로 표시하지 않습니다.

### 4.2 3번: 제공한 엔진의 앱 연결과 기술 검증

- 제공됨: #51 역방향 WDS 호스트/뷰어, 입력 권한 게이트, 판서 엔진/오버레이·전송 콜백, `MonitorDpiAdapter.GetMonitors`, WDS 맞춤/확대축소 어댑터. 엔진 전부가 없는 상태로 기록하지 않습니다.
- 남은 구현: 현재 Server 쪽 엔진을 학생 호스트/교수자 뷰어에서 재사용할 수 있게 배치하고 실제 앱 수명에 연결합니다. 학생 앱이 Server 실행 프로젝트를 직접 참조하는 우회 대신 공용 기술 경계·호출 예제를 인계합니다.
- 남은 구현/확인: 기존 viewer의 실패·거부·중지·종료 시 Close/Dispose 순서, 학생별 독립 viewer 수명, 모니터 열거 결과를 실제 공유 대상에 적용, 배율/DPI/좌표 변환 연결. Pan은 현재 어댑터가 `NotSupportedException`을 반환하므로 지원 방향·제약을 명시하고 성공으로 표시하지 않습니다.
- 검증: 실제 WDS viewer에서 발생한 마우스/키보드 입력이 선택 학생 PC에 도착하고 회수 직후 중단되는지 확인합니다. 로컬 OS 입력 시험이나 ControlLevel 변경만으로 대체하지 않습니다. 모니터/DPI·두 학생 동시 보기·중지/재시작·재접속과 판서 수신도 최소 실행 호스트에서 검증합니다.
- 학생 앱 조립은 2번 라우팅과 5번 UI 연결이 필요하지만, 엔진 제공·호출 예제·실패 종료 회귀 등 독립적으로 가능한 작업까지 대기로 묶지 않습니다.

### 4.3 5번: 기본 UI 유지와 기능 부착

- 제공됨: #65·#67의 참가/강의 화면 분리, 세션 이름/접속 코드 입력 제거, 호스트 IP·방 비밀번호 기본 UI, 채팅 Enter/부분 선택 복사, 파일 드롭/다운로드, 작은 접힘 로그와 학생 목록 기본 UI. 병합된 코드와 실제 다중 PC 인수는 구분합니다.
- 남은 연결: 현재 비활성인 모니터 선택·판서·학생 크게 보기/원격 제어를 제공 API에 연결합니다. 고정 모니터 목록은 실제 열거 결과로 교체합니다. 판서는 툴바 위치(상/하/좌/우), 도구·색·굵기, Undo·지우개·전체 삭제·숨김/재표시, 내용 유지 OFF/삭제 후 OFF와 실제 포인터/오버레이를 연결합니다.
- 남은 연결: 창 크기 맞춤·휠 확대축소, 학생별 독립 펼침과 모두 펼치기/닫기, 동시에 여러 작은 화면/큰 보기 및 제어 상태. 접기/보기 중단과 제어 회수의 정책은 2번 결과에 따릅니다.
- 검증: 참가/거부/끊김·공유 대기/복귀·권한 회수 상태와 기존 채팅/파일/비밀번호/로그 동작을 실제 클릭으로 재확인합니다. 화면 캡처만으로 버튼 동작 완료를 표시하지 않습니다.
- 요구 유지: 교수자 자기 미리보기·세션 이름·수동 접속 코드·학생 개발자 테스트 UI를 되살리지 않습니다. 교수자 화면은 학생에게 보기 전용입니다. 제공 API가 있어도 앱에 아직 부착되지 않은 항목은 '엔진 전체 없음'이 아니라 '연결 미완료'로 표시합니다.

공통 제출 기준: 최신 main을 작업 브랜치에 반영하고 위 선행 PR의 병합 여부를 확인합니다. 미완료는 **필요 API/담당/현재 제공 여부/막힌 이유/해제 조건/다음 예정 주차**를 남깁니다. 다른 파트 의존과 장비 부족에 따른 미검증을 분리하며, 담당 범위를 넘겨 완료 처리하지 않습니다.

## 5. 검증 근거와 남은 위험

- #77: 추가 23건 통과. 기존 main 송신 코드로 새 프레임 회귀를 실행했을 때 2건 실패하고 보완 후 3/3 통과했습니다.
- #77 단독: Debug/Release 각각 712 통과·39 건너뜀·실패 0.
- #78 포함: Debug/Release 각각 715 통과·39 건너뜀·실패 0, 빌드 경고 0·오류 0. 파일 TLS/TCP 회귀 13건을 10회 연속 통과했습니다.
- 위 수치는 최초 게시 당시 이력입니다. 재검토에서 무응답 프레임의 무기한 점유, 실제 엔진 `Circle`/공통 `Ellipse` 불일치, 미지원 도구·한 점 허용을 발견해 #77에서 보완·병합했습니다. 현재 공유 세대 검사도 포함했습니다.
- 프레임 하나의 송신/flush 제한은 기본 15초이며 생성자에서 변경할 수 있습니다. 대기 중 요청 취소는 즉시 반영하고, 프레임 시작 뒤에는 경계를 보존하되 제한 초과/IO 실패 시 연결을 닫습니다. 토큰을 무시하는 Stream도 송신 대기를 종료합니다. 자동 재연결 구현을 추가한 것은 아닙니다.
- 판서 호환 검증은 실제 엔진 출력 → 공통 codec → 실제 수신 레이어/픽셀 검사입니다. WDS 네트워크·최종 UI 인수와는 구분합니다. 파일 추가 회귀는 실제 TLS/TCP 종료·partial 삭제·새 연결 저장 바이트/ACK를 검사하며, 시간 초과 발생 자체는 별도 프레임 회귀로 검증합니다.
- #80 전 보완본은 Debug/Release 각각 734 통과·39 건너뜀·실패 0이었습니다. 공통 송신/계약/실제 판서 호환 41건과 파일 TLS/TCP 14건, 합계 55건을 Release에서 5회 연속 통과했습니다.
- #77 분리본 최종 전체는 730 통과였으나 첫 Release 실행에서 공유 재시작 테스트가 실패했습니다. 재현 결과 Application이 없는 호스트에서 종료/수신 콜백의 로그 목록 동시 수정이 원인이었고 #80에서 직렬화했습니다. 수정 전 회귀 실패/수정 후 통과, 같은 재연결 테스트 4,000회 통과, WPF Dispatcher 갱신/종료 시 UI 스레드 유지도 확인했습니다. 정상 퇴장 테스트의 안내 기록 전 검사 경합도 #80에서 수정했습니다.
- **최종 #77·#80·#78 통합본 Debug/Release 각각 735 통과·39 건너뜀·실패 0, 빌드 경고/오류 0.** 파일 14건도 재실행 통과했습니다. 반복 검증 중 디스크 공간 부족으로 56건 실패한 실행은 별도로 구분하고, 여유 공간이 있는 상태에서 전체를 재검증했습니다. 실패 이력을 숨기거나 건너뜀을 통과로 합산하지 않습니다.
- 무응답 송신은 요청 취소 유무 × 하위 Stream의 취소 토큰 준수/무시 4조합을 확인했습니다. 대기 송신은 종료 경합에 따라 취소 또는 disposed 예외만 허용하며, 성공·다른 예외·테스트 제한 시간 초과는 실패입니다. 최초 검증에서 이 두 종료 예외 중 하나만 기대한 테스트가 2건 실패해, 연결 종료·후속 프레임 미기록 조건을 유지하면서 기대값을 바로잡았습니다.
- 전체 실행 필터는 `FullyQualifiedName!~WindowsNativeInputPipeline`입니다. 실제 데스크톱 입력 테스트 2건은 제외했습니다. 건너뜀과 제외는 통과로 계산하지 않습니다.
- 추가 native WDS 7건 첫 실행은 **6 통과·1 실패**였습니다. 판서 전체 삭제 뒤 공유 화면 픽셀 검사 시간 초과이며, 해당 테스트 단독 재실행은 1/1 통과했습니다. 새 판서 봉투를 쓰지 않는 기존 직접 엔진/화면 검사 경로입니다. 원인을 확정하거나 완전 안정화됐다고 처리하지 않습니다.
- 이후 읽기 전용 재검토에서 해당 native 테스트를 3회 연속 통과했지만 간헐 실패 원인을 확정한 것은 아닙니다. 반복 55건은 native WDS E2E 재실행이 아니라 위 공통/렌더러/파일 회귀입니다. 이 판서 픽셀 시간 초과는 #80에서 해결한 로그 목록 예외와 다른 항목이며 3번의 실제 화면 검증에서 계속 추적합니다.
- 여러 PC, 최종 UI 전체, WDS viewer발 입력, 모니터/DPI 실측, 15분 병행, 시연 2회는 미인수입니다. 자동 테스트 수를 프로젝트 진척률로 사용하지 않습니다.
