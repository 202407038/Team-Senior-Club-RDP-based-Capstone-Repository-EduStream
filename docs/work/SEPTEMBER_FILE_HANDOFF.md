## 송신 API와 한계

StreamFilePacketsAsync(filePath, senderId, sessionId, chunkSize, cancellationToken)를 await foreach로 순회하며 즉시 전송합니다. 파일을 읽기 잠금으로 유지한 상태에서 SHA256을 계산한 후 청크를 순차 읽습니다. 호출자는 청크 목록 전체를 보관하지 않아야 메모리 절감 효과가 유지됩니다.

기존 BuildFilePacketsAsync는 호환 API로 목록을 반환합니다. 교수자 SendFileAsync는 순차 API를 사용하며 다음 청크 송신 전에 강의 세션 변경 여부를 확인합니다. 세션 변경 검사와 실제 네트워크 송신 사이의 경쟁 방지 및 수신 ACK 기반 최종 전달 보장은 2번 세션 라우팅 연동 검증 대상으로 남습니다.

수신기는 아직 전체 조립 데이터를 메모리에 유지합니다. 8MB 검증을 무제한 대용량 지원으로 표현하지 않습니다. 임시 파일 교체는 기존 파일 보존을 위한 처리이며 전원 장애 시 영구 저장 보장을 뜻하지 않습니다.

## 샘플 생성과 검증

저장소에서 PowerShell 실행:

```powershell
./scripts/New-SeptemberDemoSamples.ps1 -OutputDirectory "$env:TEMP\EduStream-September-Demo"
```

새 폴더만 허용합니다. 64KB/1MB/8MB 파일과 manifest.csv를 생성합니다. 기존 폴더가 있으면 다른 이름을 사용합니다.

학생의 저장 파일에 Get-FileHash -Algorithm SHA256을 실행해 manifest와 비교합니다. 8MB는 이번 검증용 대형 샘플 기준이며 제품 최대 크기는 아닙니다.

## 5주차 실제 RDP 병행 시연 절차

1. main 반영 커밋, OS/PC, RDP 공급자/설정과 네트워크 환경을 기록합니다.
2. 교수자 세션을 열고 학생 2명이 같은 화면을 실제 RDP로 수신하는지 확인합니다.
3. 화면에서 창 이동/스크롤을 계속하며 64KB → 1MB → 8MB 파일을 전송합니다.
4. 전송 중 교수자와 학생이 채팅하고 수신 순서 및 누락 여부를 기록합니다.
5. 학생 각각의 파일 크기/SHA256/완료 UI를 확인합니다.
6. 대상 파일을 잠근 상태에서 재전송하여 실패 문구, 기존 파일 보존, 임시 파일 정리를 확인합니다.
7. 잠금을 해제한 뒤 재전송하고 두 학생의 파일 무결성을 확인합니다.
8. checksum 오류는 자동 회귀 테스트로 재현하고, 실제 UI 주입 도구가 준비되면 별도 실사용 검증합니다.
9. 15분 이상 병행 실행과 세션 종료/재접속을 기록하고 전체 시연을 2회 수행합니다.
