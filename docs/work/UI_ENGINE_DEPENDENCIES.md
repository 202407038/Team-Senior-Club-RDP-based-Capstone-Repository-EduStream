# UI 담당 항목 중 엔진 연결을 기다리는 부분 (PR #65·#67)

기준: `feature/client-ui-fix-server`(#65)와 `feature/client-ui-student`(#67)의 UI 변경 및 팀장 보완분. #67은 #65가 반영된 main을 병합해 검증합니다.
UI 담당이 native 엔진을 대신 구현하는 것이 아니라, **엔진이 실제로 막고 있는 항목**과 **엔진 없이 끝낸 UI**를 구분해 기록합니다.
엔진이 없는 기능은 동작하는 것처럼 보이지 않도록 비활성 처리하고 이유를 화면에 표시합니다.

## 엔진과 무관하게 이번 PR에서 끝낸 UI

엔진을 기다리지 않고 구현했습니다.

- 교수자: 세션 이름 입력·접속 코드 표시 제거, `HostNetworkInfoService`의 실제 IP 선택·복사, 포트 5000 기본·고급 설정, 방 비밀번호 사용 여부를 세션 열기 전에 선택(열린 뒤 변경 불가 안내), 작은 기본 접힘 로그, 채팅 선택·복사·Enter/Shift+Enter, 학생 목록 기본 접힘과 갱신 시 펼침 상태 유지, 외부 파일 드롭 등록.
- 학생: **공유 화면 맞춤(U04 기본 동작)** — 뷰어 `SmartSizing`을 켜고 `OnSharedDesktopSettingsChanged`로 받은 공유 데스크톱 크기(예: 1920×1080)의 비율로 표시 영역을 맞춰, 전체 화면이 스크롤·잘림·늘림 없이 보이고(남는 쪽은 여백) 창 크기를 바꿔도 비율이 유지됩니다. RDP가 연결되면 PNG 방식의 "프레임 없음" 표시는 숨깁니다. 접속 코드 입력·검사 제거, 교수자 IP 입력, 포트 고급 설정, `SecureRoomJoinClient.AuthenticateAsync(host, port, displayName, password, ...)` 호출, 파일명 클릭 다운로드, 채팅 선택·복사.
- 회귀 테스트: 보기 허용 OFF→ON(공유 전/공유 중), 공유 중지·재시작, 퇴장 뒤 복귀 금지.

## 구현 없음과 미검증의 구분

- **구현 없음(엔진 API 부재)**: 위 표의 다섯 항목.
- **미검증**: 서로 다른 PC에서의 실제 수신 화면, 서로 다른 해상도/DPI와 보조 모니터, 학생 2명 화면을 눈으로 확인하는 최종 통합 시연. 아래 로컬 검증을 다중 PC 실사용 완료로 확대하지 않습니다.

## 2026-10-05 보완·검증 및 후속 작업

- #65: 판서 설정 값을 독립적으로 준비하고 실행 불가 이유를 표시합니다. 설정을 펼쳤을 때 중앙 열을 스크롤해 파일·로그에 접근할 수 있습니다. 이 보완은 실제 판서 엔진 구현이 아닙니다.
- #67: 참가/퇴장 시 주 모니터로 이동하지 않고 현재 모니터·창 위치를 보존하며 화면 밖으로 나가는 만큼만 보정합니다. 좁은 참가 폼 잘림과 참가 후에도 참가 전 안내가 남는 문제를 수정합니다.
- 직접 실행: 참가 폼 최소 너비, 로컬 세션 참가/퇴장에 따른 창 위치 유지, 교수자 설정 확장과 로그 접근을 확인했습니다. 안내 문구는 실행 중 발견 후 상태 전환 자동 테스트로 재검증했습니다.
- 자동 검증: 창 좌표·DPI 환산 후 경계 보정, 참가/재연결/퇴장 안내, 판서 설정과 실행 비활성을 검증합니다. 별도 `EDUSTREAM_WDS_SMOKE=1` 실행은 실제 WDS 구성요소를 사용하는 로컬 연결 테스트이며 화면 픽셀이나 다중 PC 실측 검증을 대신하지 않습니다.
- 기존 파일 취소 테스트 `CancelAfterFirstSavedChunk_RemovesPartialAndAllowsNewRequest`의 간헐 실패는 별도 이슈이며 이번 UI 보완으로 해결했다고 처리하지 않습니다. 최종 실행 결과와 재실행 이력은 PR 보완 댓글에 기록합니다.
- **이번 머지는 UI 변경분 선반영이며 UI 담당의 전체 작업 완료가 아닙니다.** #51의 실제 엔진 구현이 검증·반영되면 5번 UI 담당자가 최신 main을 기준으로 모니터 선택, 판서, 확대·축소/이동, 학생 화면 작은/큰 보기, 원격 제어를 실제 어댑터에 연결하는 후속 PR을 진행합니다.
- 후속 PR은 버튼 활성화만으로 완료하지 않습니다. 교수자/학생 양쪽 실제 결과, 공유 재시작·퇴장·권한 회수, 실패 시 대기/오류 표시까지 확인합니다. 미완료·장비 미검증은 구분해 기록합니다.
