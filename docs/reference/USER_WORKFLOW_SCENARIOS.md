# EduStream 사용자 워크플로우 시나리오

이 문서는 현재 프로젝트 상태, 구현 목적, 주요 사용자층을 기준으로 예상 가능한 대표 사용자 흐름을 정리한 문서입니다.

현재 기준 대표 시나리오는 "교수자의 실시간 강의 화면 공유 및 파일 배포"입니다.

## 1. 시나리오 개요

- 시나리오명: 교수자의 실시간 강의 화면 공유 및 파일 배포
- 주요 사용자:
  - 교수자
  - 수강생
- 사용 목적:
  - 교수자가 자신의 화면을 여러 수강생에게 실시간으로 보여준다.
  - 강의 자료 파일을 함께 배포한다.
  - 텍스트 채팅으로 간단한 질의응답을 진행한다.

## 2. 사전 조건

- 교수자는 `EduStream.Server`를 실행할 수 있다.
- 수강생은 `EduStream.Client`를 실행할 수 있다.
- 교수자는 세션 접속 정보(IP/Port)를 수강생에게 전달할 수 있다.
- 서버와 클라이언트는 서로 연결 가능한 네트워크 환경에 있다.

## 3. 기본 사용자 흐름

### 1. 교수자가 서버 프로그램을 실행한다.

- 교수자는 강의 시작 전에 `EduStream.Server`를 실행한다.
- 세션 이름과 포트를 확인하거나 입력한다.

### 2. 교수자가 강의 세션을 개설한다.

- 교수자는 "세션 열기" 기능을 실행한다.
- 시스템은 세션 정보를 생성하고, 수강생이 접속할 수 있는 상태가 된다.

### 3. 교수자가 수강생에게 접속 정보를 전달한다.

- 교수자는 강의 공지나 메신저를 통해 IP와 Port를 안내한다.
- 수강생은 전달받은 정보를 기준으로 접속 준비를 한다.

### 4. 수강생이 클라이언트 프로그램을 실행한다.

- 수강생은 `EduStream.Client`를 실행한다.
- 필요하면 표시명 또는 이름을 입력한다.

### 5. 수강생이 세션에 참여한다.

- 수강생은 교수자가 제공한 IP/Port를 입력하고 세션 참가를 요청한다.
- 시스템은 참가 요청을 처리하고, 승인되면 연결 상태를 갱신한다.

### 6. 교수자가 화면 공유를 시작한다.

- 교수자는 "화면 공유 시작" 기능을 실행한다.
- 시스템은 교수자 화면을 캡처하고 전송 가능한 데이터로 준비한다.

### 7. 수강생이 공유 화면을 실시간으로 본다.

- 클라이언트는 전송된 화면 데이터를 수신한다.
- 수강생은 교수자 화면 또는 강의 자료 화면을 실시간으로 본다.

### 8. 교수자가 강의 자료 파일을 전송한다.

- 교수자는 파일을 드래그 앤 드롭하거나 파일 전송 기능을 실행한다.
- 시스템은 파일 메타데이터와 체크섬을 생성하고 파일 데이터를 전송 준비한다.

### 9. 수강생이 파일을 수신하고 저장한다.

- 클라이언트는 파일 패킷을 수신한다.
- 시스템은 체크섬 또는 전송 상태를 검증한 뒤 파일을 저장한다.
- 수강생은 다운로드 완료 상태를 확인한다.

### 10. 교수자와 수강생이 채팅을 사용한다.

- 교수자는 공지나 설명을 채팅으로 보낸다.
- 수강생은 질문을 채팅으로 보낸다.
- 시스템은 메시지를 송수신하고 각 화면에 표시한다.

### 11. 강의 종료 시 세션을 닫는다.

- 교수자는 수업 종료 후 세션 종료를 실행한다.
- 시스템은 연결 종료 절차를 수행한다.
- 수강생 클라이언트는 세션 종료 상태를 표시한다.

## 4. 기대 결과

- 교수자는 복잡한 설정 없이 강의 세션을 개설할 수 있다.
- 수강생은 간단한 접속 정보 입력만으로 강의에 참여할 수 있다.
- 화면 공유, 파일 배포, 텍스트 채팅이 하나의 흐름 안에서 동작한다.

## 5. 현재 프로젝트 기준 의미

- 현재 작성된 UML, 패킷 구조, 세션 흐름 스켈레톤과 가장 잘 맞는 기준 시나리오이다.
- 이후 채팅, 파일 전송, 화면 스트리밍 구현 시 공통 기준 흐름으로 활용할 수 있다.
- 향후 예외 상황 시나리오나 테스트 케이스로 확장할 수 있다.
